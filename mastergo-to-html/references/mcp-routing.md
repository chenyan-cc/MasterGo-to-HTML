# MCP 发现与路由

工具名称因提供方而异，以下是已知适配示例，必须根据当前发现的工具签名调用，不假设它们一定安装。读取工具返回的操作约定。不要把设计转代码误路由为生成设计稿。

默认使用 MasterGo Vibe 前端导出路径，按工具能力识别，不依赖固定 server 名称。用户已指定或本项目已验证的路线优先复用。只有主路线缺少必要能力且另一条路线已知可用、能访问同一目标时，才切换一次并记录原因；不为同一目标同时读取两套结构。缺少访问权限时先报告，不用切换服务绕过权限。

## MasterGo Vibe 前端导出路径

- `get_frontend_code(frontendFramework="html", targetNodeId=<链接>, projectDir=...)` 可导出 HTML 初稿；先明确 HTML 输出文件名，必要时在授权工作区暂存，最终整理 HTML/CSS 和素材到桌面交付目录。
- `get_screenshot` 获取同一目标的原图。
- `get_variables` 可能针对当前连接文件；必须验证连接文件与链接文件一致，不能混用。
- `get_selection_node` 是节点快照能力，不自动等同于前端代码导出。
- 遵守导出返回的 frontend-code-review.md（如有）。导出后读取代码、对照原图并改进布局，不再次询问是否需要必要的代码整理。
- 后续微调不重新调用导出覆盖已有代码；需要设计参考时获取截图。

## MasterGo Magic 分区路径

- 完整页面从 `getDesignSections` 获取分区列表，再读取每个 sectionIndex。页面级链接可用 `getPageLayers` 定位目标，不能从纯文件 ID 假设可列出页面。
- `getDsl` 仅在分区工具失败且适配方允许时作为回退，不为同一设计重复混用两种读取链。
- 使用该路径规定的 SVG/文本占位符，遵守每个节点的准确素材键；最后调用 `applyDesign` 完成替换与输出，不能遗留占位符。
- 如工具约定 applyDesign 后不得编辑最终产物，则保留可维护源文件，在源文件进行 QA 修正并重新 applyDesign；不直接修改最终产物。若此限制影响文件拆分，记录限制，不能虚称已完成拆分。
- 只读取设计相关文档链接，不调用 C2d 等回写设计能力。

## 其他提供方

只有实际存在 `get_selection_code` / `get_selection_image` 才使用这些名称，且验证当前选区与用户目标一致。无法由当前工具完成目标访问时报告能力缺口，不虚构工具、不用写入请求测试连接。
