# 项目规则与移动适配

用户提供现有开发页面或源码时，只读入口及实际相关样式、业务区块和图表资源。优先读取本项目记录，首次补齐必要证据，后续仅在相关资源、环境或需求变化时复核。工具超时按浏览器准备的有界恢复规则处理；不能把读取到公共样式当作业务区块已核实。

在已有项目记录中保存：设计基准宽度、采用的单位、手机铺满范围、宽屏策略、字体来源/字重、颜色变量、主布局、滚动容器及图表策略。记录资源路径或选择器依据，不保存凭据、不硬编码本机路径或某个内网项目地址进技能。不新增无收益的报告文件。

## 有项目约定时

- 优先沿用项目规则，不能仅因看到Vue入口就改为Vue交付。生成组件仅在用户指定技术栈时进行。
- 若项目采用vw，按实际画板基准W换算：设计尺寸 / W × 100vw。字号、间距、圆角、图标等分别判断；容器通常用100%、flex及内容尺寸。细边框、分隔线、固定触控目标不机械同比换算。不用transform整页缩放。
- 在320–440px验证设计比例及可读性；不能只删除max-width而保留写死的内部宽度。宽屏按项目约定处理；无约定时对字体、空间及容器设置有依据的上限，且比例单位与容器上限协调，不能只封顶容器却让内部vw继续增大。
- 复用已确认可用的字体地址、字重映射、变量和共享组件样式；缺少字体证据时说明回退。只读到日夜变量并不意味着需要额外实现夜间页面。字体嵌入遵循可用授权，不打包未经确认的文件。
- 项目采用页面Flex纵向、内容独立滚动时，检查父级高度约束、flex子项min-height:0及底部可达性；不要叠加多套无意嵌套滚动。

## 没有项目约定时

默认手机宽度内铺满，以正常流、Flex/Grid、内容自然增高为骨架；字体保持可读，按内容需要换行或改变排列。不要将任何一张原稿的393px推广为通用宽度，不默认全量vw或设备型号断点。

## 一次确定区块策略

- 卡片：重复组件共享规则，明确列数、伸缩、min-width:0及内容换行；按真实二维结构选择Grid。
- 表格：明确列对齐、必要最小宽度及是否局部滚动，保留真实行数与数值。
- 图表：先核实项目图表容器和缩放机制。原始SVG优先保留；可响应式绘制时随容器调整，密集标签确需保持可读宽度时局部滚动并验证末端。不默认固定369px，不编造数据或路径。
- 定位：修改父容器position时核对后代定位上下文；重点检查说明框、角标和图表叠层。
- 素材：布局修复前统一检查零尺寸SVG、viewBox/裁切/变换、蒙版与PNG透明通道；修复依据是原始素材与参考图，不能统一替换所有蒙版类型或虚构路径。
- 语义：重复组件采用一致的用途类名；保持原有工具要求保留的类，新增语义类。徽标、来源、数据标签按用途处理，不按ID批量改成标题。静态数据和待接入交互在交付说明标明，不伪造成功状态。

这些判断并入首次读取与现有修改批次。默认最多三轮，中间检查受影响区域和宽度，最终一次全尺寸扫描；不因每项规则新增启动浏览器或重复读取设计。
