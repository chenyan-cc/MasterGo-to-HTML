# QA 与交付检查

## 阶段与通过条件

顺序为：原尺寸初次对照与修复 → 逐区代码整理并回归 → 响应式适配并回归原尺寸。未通过原尺寸视觉验收时，不做大范围布局改写。原始导出也必须与设计原图比较，不是默认正确答案。

首次保存原始导出及截图作为回归材料；后续增量修复不重新拉取代码。每批修改保留一份可恢复状态；耦合区域逐区复核，独立区域可共享一张前后整页截图并按区域查看差异。小范围修改优先截图受影响区域，移动了后续文档流时包含后续区域。变差则撤回对应改动。不能把保留局部定位认定为验收失败，也不能通过批量尺寸转换追求代码指标。

基准截图必须明确记录实际 viewport、页面容器宽度及 DPR。宽屏默认将交付内容限制在设计原宽并居中，基准预览使用等于设计宽度的真实视口。更宽手机铺满需独立布局与验收，不静默扩大为任意上限。

## 最少充分检查

- 初次：一次原尺寸完整截图，同时收集资源、控制台、尺寸及实际字体证据；列出问题后集中修复，避免一个问题一个往返。
- 中间：只检查本批改动涉及的区域与宽度。局部颜色/图标修改不触发全部宽度；全局字号、布局或断点变化才扩大回归范围。
- 最终：同一浏览器批次检查原尺寸及 320、360、375、390、393、414、430（去重）和一个宽窗口。每个宽度做技术检查；完整查看原尺寸、最窄宽度以及有不同排布/断点的宽度，其余查看差异区域。记录哪些宽度做过完整视觉检查，不能把技术扫描表述为逐页视觉通过。
- 最终批次一并验证真实交互、必要长文本场景和资源/控制台；已有合格结果且文件未改不重复运行。交付复制后核验文件一致性即可，不再把完全相同文件重复截图。
- 默认交付原稿参考、初次导出、最终截图和精简结果；中间全套源码快照放工作目录恢复区，最终包只保留解释遗留问题所需的中间材料，不为没有问题的区域生成重复报告。
- 明确剔除有意裁切的装饰和可滚动图表后再判断异常溢出，并验证滚动能到达末端；不要反复追查已说明的预期几何越界。

## 必查视觉区域

按页面实际区域检查并记录“原稿依据 / 问题 / 修改 / 复核 / 剩余差异”：

- 顶部：背景覆盖宽度、装饰位置、标题、图标和导航状态。
- 卡片：实际可视数量、边缘裁切、留白、间距及有意滚动。
- 说明：图标与首行对齐、多行换行、强调文本及段落高度。
- 时间轴：圆点与轨道中心、标签与日期对应、当前状态及渐变范围。
- 表格：列对齐、行数、状态、数字、行高和窄屏可读性。
- 图表：原始 SVG、坐标和图例、数据标签、裁剪与宽高比例。

技术检查与视觉验收分别记录通过/未通过/未检查。不得因资源可用或整体区块坐标一致而将所有视觉项标为通过。字体加载 API 不足以证明指定字体真实存在，不用它作为字形一致的证据。

## 截图条件

固定视口、deviceScaleFactor、浏览器与截图范围；基准宽度与画板一致，长页使用完整截图。按 [浏览器环境准备](browser-preflight.md) 设置有界的字体与图片等待，记录加载失败或超时；关闭动画与过渡，避免因时序产生假差异。未就绪截图不能作为通过依据。

对照原图检查整体和局部，必要时叠图。字体抗锯齿差异与真实布局差异分开记录，不仅凭单一像素分数判定通过，不宣称未经量化的还原百分比。

## 验收项

- 内容：文本、图标、行数、变体和状态准确，没有未替换的工具占位符。
- 视觉：主结构、尺寸、对齐、背景、文字换行、素材比例与裁切一致。
- 适配：基准宽度及 320、375、390、414、430 至少各检查一次；其余兼容宽度如未实测必须区分说明。检查非预期横向滚动、重叠、裁切、底栏遮挡与安全区域。
- 运行：本地资源可加载；检查页面错误与控制台相关错误；验证已有交互，不测试不存在的后端能力。
- 维护：主布局规则清晰，重复 CSS 已合并、过时覆盖已清理；主要区块和组件使用语义类名，HTML/CSS/脚本引用一致，设计节点映射仍可追溯。无无理由的大量坐标定位；适当检查长文本变化不会破坏布局。
- 语义与替代文本：在同一最终检查批次查看标题大纲、图片用途及可访问名称。确认主标题和区块层级合理；img 均有符合用途的 alt，装饰图允许空文本，不能仅以“存在 alt 属性”判定通过。信息图表有摘要或关联说明，图标控件有动作名称。结合现有原尺寸回归检查标题默认样式、CSS 合并和类名替换未改变外观；不额外启动浏览器或重跑无关尺寸，不以这些检查声称完整无障碍合规。

记录初次检查与每轮“问题 / 相关文件或区域 / 修改 / 复核结果”，轮数按 SKILL.md 定义累计，复核后继续修复计下一轮。新增修改只回归受影响范围，无新问题时停止。

## README 报告结构

1. 设计来源、文件/画板身份、基准尺寸、MCP 访问验证结果。
2. 文件清单与运行方法：双击同名 HTML；HTTP 需要时给出已经验证的命令、目录与地址。
3. 区块及布局策略，响应式推导与字体回退。
4. 初次 QA 和最多三轮修复记录，实际测试尺寸与浏览器。
5. 剩余问题、缺失资源及对应节点、待补交互；无问题时如实说明。
6. 简短阶段计时；无法测得的授权/等待时间明确标注，避免事后猜测。

报告额外注明：基准宽度、实际页面宽度、默认最大宽度、重构前后结果、各区域视觉结论，以及响应式规则是否再次通过基准回归。最多三轮是本次整个修复周期的总预算，不是每阶段三轮。保存已验证版本并明确剩余问题；不因为预算耗尽宣称验收通过。

截图如需保存放入 qa/，文件列表同步更新。最终交付包不包含凭据、MCP 配置密钥或用户无关的工作区文件。
