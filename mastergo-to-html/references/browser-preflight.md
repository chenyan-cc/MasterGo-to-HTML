# 浏览器环境准备

用于本地生成页面的 QA。设计截图由 MasterGo MCP 提供，页面验收由浏览器完成，桌面交付是文件操作；三者分别验证，不把一个环节失败当作全部连接失败。

## 选择一条主路径

遵守宿主工具限制和用户指定的浏览器。已有本任务成功使用的会话时直接复用。否则：本地生成页面优先复用当前环境已验证的 Playwright/浏览器运行时；没有可用本地运行时才选已连接且具备读取、截图、尺寸控制能力的浏览器工具。用户指定浏览器时先用指定路径，能力不足明确说明，不私自换用工具绕过权限。

工具目录存在、标签页可列出、网页能打开，都不证明页面内容读取和截图可用。不要为本地页面 QA 要求用户登录 Chrome、配置扩展或授权飞书。远程业务页面的操作失败不直接证明本地 Playwright 不可用。

## 一次最小探测

1. 复用已知运行时路径和项目依赖；未知时只查询一次宿主运行时信息或项目依赖。不要全盘搜索 node_modules、反复尝试全局包或下载多套浏览器。
2. 在可写工作区准备一个含本地 CSS、图片和中文文本的最小页面，验证启动、加载、DOM 读取、指定视口和截图保存。已有目标页面时直接使用它，并把探测结果作为初次 QA，不另建重复测试。
3. 先做脚本语法和依赖解析检查，再启动浏览器。实际字体在目标页面检查，缺字或回退不触发盲目安装字体或扫描全盘字体。
4. 同一任务记录一次路径、浏览器版本、启动方式、页面访问方式、会话状态及探测结果。仅会话失效、依赖变化或出现新错误时重新探测受影响项；跨会话不能仅凭旧记录声称环境正常。

## 访问与等待

简单静态页面先使用 file://。需要模块、fetch 或同源能力时，使用已存在的本地服务，或仅绑定 127.0.0.1、根目录限定为项目目录的临时静态服务。结束时关闭自己启动的服务，不终止用户已有进程。

不要依赖 file:// 下外部样式表的 cssRules 可读性。需要检查 CSS 时读取工作区源文件；渲染后的结果用受支持的 DOM/计算样式能力查看。通过浏览器控制工具时遵守其只读求值约束，不用底层脚本越权编辑页面。

可配置时，单次启动/导航/截图设约20–30秒超时，字体与图片等待设约10秒上限；按实际慢任务证据调整，不将其视为平台保证。不要默认等待 networkidle，也不要固定 sleep 等待资源。超时后明确记录未就绪项，不将残缺截图判为验收通过。工具不支持超时参数时不杜撰参数，调用返回后遵守下述停止条件。

## 有界恢复

- 沙箱拒绝启动或网络访问：按环境规定申请针对性授权后重试；不要换工具绕过沙箱，也不要把权限拒绝误判为缺少依赖。
- 包或浏览器缺失：先用已知现有运行时。确实需要安装时说明具体缺项和安装范围，遵守授权要求；不自动升级项目依赖或安装整套工具链。
- 脚本错误：根据错误做明确修正，再试一次；不通过换脚本文件名重复申请相同检查。
- 控制通道超时：只允许一次有依据的恢复尝试。仍失败时停止同一路径；仅有已知可用、宿主允许的替代路径才切换一次。不要在 Chrome、内置浏览器和原生窗口之间循环试错。没有状态变化的新回合也不重复失败探测，用户明确要求重试除外。
- 默认环境准备的主动探测与恢复预算为约2分钟，不包含用户授权等待、用户明确同意的安装和正常页面 QA。达到预算后停止环境排障，报告阻塞与可恢复步骤；可继续有设计依据的代码和静态检查，但视觉 QA 必须标为未完成，不能继续依赖视觉通过的布局重构。

## 复用与耗时

首次准备固定用途、可审查的 QA 入口，参数只包含目标页面、输出目录、尺寸和阶段。检查逻辑与页面修改脚本分开；不要将任意 shell 执行、任意代码加载或扩展写入范围加入已批准入口。需要变更能力时重新走适用授权，不能靠固定文件名规避审批。

同一会话 reload 后完成区域回归和最终尺寸检查；没有持久会话能力时，每批只启动一次浏览器。现有技能尚未附带通用 QA 执行脚本，不得声称仅凭本说明已实现标准工具或免授权。

分别记录环境探测、依赖安装、实际 QA 和可测授权等待的耗时；不可测部分标为未知。环境故障不计为页面修复轮次，但受环境恢复预算约束。
