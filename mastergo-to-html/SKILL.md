# MasterGo 移动端 H5 生成器

用户提供 MasterGo 链接即可开始；默认输出原生静态 HTML/CSS/JavaScript，不引入无必要依赖。只读设计稿，禁止修改或覆盖 MasterGo 原始设计。不得调用画布提交、同步、更新、替换、删除等写入工具。

## 执行效率与授权

- 首次浏览器准备先读 [浏览器环境准备](references/browser-preflight.md)，按其中的选路、最小探测及失败停止规则执行。环境预检只做一次；设计读取与独立环境探测可并行，不重复扫描工具目录、依赖或字体。
- 先检查导出资源的 SVG 零尺寸、viewBox/裁剪/变换、PNG alpha 及实际字体，再定位视觉差异；不通过猜测 opacity、blur 或缩放掩盖导出问题。
- 尽可能在同一个持久浏览器会话内完成初次截图、区域回归、尺寸检查、资源/控制台、实际字体及交互检查；修改后 reload，不为每个区域另启浏览器。会话不可用时，将同一批只读检查放进一次浏览器进程。
- 优先复用现有检查工具。需要新脚本时，先准备完整、可审查、用途固定的检查脚本，限制到目标页面和 QA 目录；不要不断创建不同临时脚本造成重复授权。
- 已有用户任务授权的普通实现、修复和验收不重复确认。需要越过沙箱时仍走标准授权；同用途、已准备好的操作可合并申请，支持时提出范围明确的持久命令规则。不得以通用 node/python/shell 前缀或事后扩展已批准脚本能力绕过审批。
- 浏览器执行、桌面写入、MCP 和操作系统隐私权限可能独立控制；不承诺“一次批准后所有操作免授权”，不擅自更改全局权限。桌面复制在验收结果和文件包准备好后一次执行。
- 记录阶段起止时间；将可测的执行时间、等待授权时间分别记录，不把无法测量的等待归因给用户。无新改动或问题不重跑已通过检查。

## 1. 连接与输入校验

先读 [MCP 适配说明](references/mcp-routing.md)，发现当前实际提供的 MasterGo 工具，并执行针对该链接的实际只读请求。发现工具名称或版本查询成功，不等于目标设计可访问。

解析链接并锁定文件、页面和目标画板身份；后续结构、截图、资源必须对应同一目标。保留原始链接及身份记录。短链接按工具能力解析，不猜 ID。链接不能确定唯一画板时，先读取轻量候选；仍不明确再询问。没有链接时请求用户提供链接。

无 MCP、服务不通、权限不足、链接无效或必要结构读取失败时，停止依赖这些数据的生成，说明具体失败、已验证事项和恢复方式。不得假装连接成功，也不得仅凭想象还原。不要自动安装 MCP 或索取用户凭据。

## 2. 读取与完整性检查

选择一条与实际工具相符的主读取路径，遵守该路径的返回约定。获取画板代码或结构、预览图、尺寸、文字、样式、图片和 SVG；分区路径必须读取全部分区并记录索引，避免遗漏。按需读取目标实际使用的变量、组件实例、变体与文档，不扫描无关库。

检查层级、文本、变量及资源引用是否可解析。保留准确文案、列表行数、选中态与按钮变体，不依据分页总数补造数据。图片和 SVG 优先使用原始素材；仅在有权导出时本地化至 assets/。不编造 SVG 路径，不替换为不相关图片。字体缺失记录实际回退及其影响，不声称回退字体等价。

缺失非关键素材时保留原尺寸和中性标记，并记录节点及待补资源；缺失关键结构或参考图时，不将结果标为完整高保真交付。截图不可用时可继续有依据的实现，但明确视觉 QA 受阻。

## 3. 原尺寸还原优先

先按画板原始宽度建立基准版本；393px 仅是画板宽度为 393px 时的基准，不作为所有设计的固定值。保存初始导出截图及原始代码快照（只在首次生成创建，后续不重新导出）。如果原始导出存在偏差，先局部修复，不能把初稿本身视为正确参考。

识别 Header、Banner、Section、Card、List、Form、Footer、Overlay。先以原图验收各区域的布局、背景、字体、换行、图标、图表和裁切，再开展维护性整理。有明显偏差时先修保真问题；缺少参考或三轮内未解决时报告未通过，不继续做依赖视觉通过的布局重构。

## 4. 逐区整理代码

保真是代码整理的约束。保持真实文本 DOM、语义化 HTML，禁止整页图片和全节点绝对定位。不引入无必要依赖。仅在有设计依据的交互确实需要时生成 main.js，不伪造业务成功。

先做不改变布局的整理：提取 CSS、去重样式、使用颜色变量、语义类名及节点映射。注意 CSS 提取后的优先级、继承、默认标签样式和空白变化，不能假设这些整理天然无视觉影响。

整理时落实以下交付要求，合并进现有修改批次和最多三轮预算：

- 合并重复 CSS：按最终有效样式整理，删除已被替代的临时修复声明和无用选择器；将共享规则归入组件类或变量。保留有意的媒体查询、状态差异、回退和必要优先级，不机械按文本去重，也不靠持续追加覆盖或 !important 交付。
- 完善语义类名：主要区块、重复组件及关键内容使用表达用途的名称（如 quote-price、inventory-chart）；整理范围内替换 design-style-XX 等自动编号类。保留 data-node-id 供设计追溯，不将其作为主要业务样式接口；同步更新 HTML、CSS 和已有脚本引用。复杂局部导出结构可保留并说明，不为全量改名增加无收益重构。
- 图片替代文本：逐张按用途处理 img；信息图片提供简洁、准确的 alt，纯装饰或与邻近文本重复的图片使用 alt=""。图片按钮/链接由控件提供动作名称，避免重复朗读；不以文件名或 title 代替 alt。图表提供有依据的摘要或关联文本，不编造数据；有意义的内联 SVG 和背景图片也应有等价可访问说明。
- 标题层级：以现有页面主标题作为 h1，主要内容区使用 h2，真实子区块按嵌套关系使用 h3 等，不按字号选级或跳级，不把每个数据标签变成标题。显式设置 margin、font、line-height 等以保持设计外观；页面语言与内容一致，不为补层级虚构可见文案。

主骨架尽可能用正常流及 Flex/Grid；必须逐区判断固定尺寸、内容尺寸、弹性尺寸和装饰坐标，禁止批量把 px 或 left/width 换成百分比，禁止按节点宽度阈值自动转换。SVG 的视口、变换、裁剪及图片行内基线分别检查，不用统一缩放掩盖错误。

按区域判断并整理布局。共享样式、定位上下文或尺寸耦合的区域逐区修改并复核；互不影响的区域可在同一批中整理，共用一个恢复快照和一次原尺寸截图，再分别检查受影响区域。不因每个 div 或 section 单独启动浏览器、复制整套文件或截整页。若视觉变差，撤回对应区域变更。复杂局部定位可以保留并说明，不能为了降低 absolute 数量损坏还原。不把这一权衡当作额外审批步骤。

## 5. 响应式与 QA

读取 [QA 与交付要求](references/qa-delivery.md)。使用实际可用的 Playwright 能力，等待字体及图片就绪，固定 DPR、动画与截图范围；不可用则明确视觉 QA 受阻。

基准预览与响应式预览分开：基准预览使用真实视口宽度等于画板宽度，不能只缩放浏览器画面或依赖百分比宽度。可用独立的带明确宽度和高度的预览框或自动化浏览器视口，不把预览工具栏混入页面内容。普通宽窗口中交付页面默认以原稿宽度为 max-width 居中，较窄屏幕流式适配；只有明确需要在大于原稿的手机宽度铺满时，单独实现并验收该行为，不任意设为 480px。

在原尺寸还原及逐区整理通过后，再单独添加移动端规则。兼容 320、360、375、390、393、414、430 CSS px；适配只能按区域有依据地推导。设置 viewport、border-box，不禁用缩放，不整体 transform:scale，不机械缩放所有文字与控件。处理图片、长文本、安全区、底栏。修改响应式规则后重新检查原始宽度，不能损坏已通过的基准。

区分技术检查与视觉验收：资源无错、无溢出、区块坐标一致不等于还原通过。顶部、卡片、说明图标、时间轴、表格及图表分别检查，留存问题与复核结果；按区域实际内容选择检查项。只声称实际验证的内容，不以轮次数或工具成功代替通过结论。

每次新生成或用户明确反馈的增量修复，初次检查后最多三轮。每轮是“列出当前已知问题 → 一批有依据的修改（含本轮重构或适配）→ 一次回归判定”；复核后因新发现问题继续修改，必须计入下一轮，不得把多次修复—复核塞入同一轮。总预算涵盖基准、重构回归及适配，不按阶段重置；轮内多尺寸只读检查不另计修复轮次。优先修保真问题，能通过则提前结束；预算耗尽停止自动修改并交付实际状态及剩余差异。用户后续明确要求继续修复可开启新的最多三轮周期。

后续反馈直接增量修改现有文件，保护人工改动，不重新导出覆盖。页面支持直接打开及相对路径资源；若需要 HTTP，说明限制和实际验证方式。

## 6. 桌面交付

默认交付到用户实际桌面目录下的 <设计稿名称>/，不硬编码用户名；跨平台按宿主方式定位桌面，不猜 OneDrive 等重定向路径。优先画板名称，失败时用文件名；安全替换文件名非法字符、防止路径穿越，保留可读中文。同名不同来源使用编号区分；来源相同增量更新。写入桌面需要权限时使用环境标准授权流程，不绕过。

输出 <设计稿名称>.html、style.css、assets/、README.md；main.js 仅在有交互时生成。禁止默认 index.html。多画板明确区分输出及对应关系。

README.md 必须明确原始宽度、默认预览的实际页面宽度、响应式上限及推导规则，分别报告原尺寸视觉验收、重构回归和适配结果，不使用无证据的还原百分比。README.md 包含文件清单、区块策略、运行方式、MCP 校验结果、实际检查尺寸、QA 轮次与修复、剩余差异、缺失素材和需补业务逻辑。提供双击 HTML 的说明；需要 HTTP 时记录实际可用的静态服务器命令和地址，未启动不编造地址。手机预览需实际可达的局域网地址。

最终返回交付目录和 HTML 的可点击绝对路径，并简要报告检查结果与局限。达到轮次上限不等于通过验收。
